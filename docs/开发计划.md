## 1. 总览

- **投入假设**：全职 ~8h/天，按工作日（周一至周五）排布；周末为缓冲，拖期任务用周末消化，**不顺延后续日期**。
- **第一阶段（M1）按天细化**（Day 1–10），后续阶段列里程碑，进入前再细化。
- **里程碑概览**：

| 里程碑 | 内容 | 预估周期 | 计划区间 |
|---|---|---|---|
| **M1 通信打通** | 工程初始化 + 数据层 + Modbus TCP 任务通道（模拟器联调） | 10 个工作日 | 11-10 → 11-23 |
| M2 核心引擎 | SctStrategy 触发/选择/优先级 + Correction 单点/两点/干扰迭代 + Workflow 状态机 + 并发队列/资源锁 | ~2 周 | 11-24 → 12-07 |
| M3 UI 全功能 | 六页界面 + HandyControl 绑定 + 四级报警面板 + 模式/急停交互 | ~2 周 | 12-08 → 12-21 |
| M4 GNR 对接 | 协议 100–140（CYCLE_START / SAMPLE_POSITIONED / RESULT_REQUEST）+ 系数闭环 + RESULT_DATA_REQUEST 扩展（与 GNR 协商） | ~1.5 周 | 12-22 → 12-31 |
| M5 联调验收 | 视觉选点/测高、归档打标、现场联调、部署与验收 | ~1 周 | 2027-01-04 → 01-08 |

## 2. 第一阶段（M1）每日任务

### Day 1 · 11-10（周二）｜工程初始化

- [x] **目标**：可编译运行的空壳工程，rules 全部生效（✅ 2026-11-09 提前完成：SDK 8.0.427、7 个登记依赖、build 零警告、test 1/1、冒烟启动通过）
- **任务**：
  1. `dotnet new` 创建解决方案与三个工程，目录对齐现有骨架（`src/SpectroscopicAnalysis.Host`、`tests/SpectroscopicAnalysis.Tests`）
  2. 引入依赖并确认与开发规范第 1 节登记一致：HandyControl、NModbus（或 FluentModbus）、Serilog、Microsoft.Extensions.Hosting、xUnit
  3. Generic Host + DI 骨架（App.xaml 启动改造）
  4. 工程级 `<Nullable>enable</Nullable>`、`<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`、`.editorconfig` + Roslyn 分析器
  5. 建立模块目录 csproj 内的文件夹结构（七个模块）
- **产出**：可运行的空主窗口；解决方案结构图更新进开发规范第 2 节
- **验收**：`dotnet build` 零警告；应用启动无异常

### Day 2 · 11-11（周三）｜主题与主窗口框架

- [ ] **目标**：主框架与原型 `dashboard.html` 目视一致
- **任务**：
  1. `Themes/` 四资源字典落地：Colors.xaml（界面规范 3.x 全部色值）、Brushes.xaml、Typography.xaml（字号阶梯）、Styles.xaml
  2. 引入 CommunityToolkit.Mvvm（已登记）；建 `Views/`、`ViewModels/`、`Converters/` 目录骨架，主窗口接 `MainViewModel`（DI 注册，严格按开发规范 3.3 分层）
  3. 主窗口三区布局：顶栏 56px（品牌/模式切换/心跳灯/时钟/用户/急停钮）+ 左栏 240px（导航 + 设备状态固定区）+ 内容区
  4. 六页导航占位页（主控台/样品档案/SCT 管理/系数管理/日志报警/设置）
  5. 模式切换按钮组（ICommand 命令绑定，交互逻辑在 ViewModel）
- **产出**：主窗口框架 + Themes 字典
- **验收**：与原型对照目视一致；grep 全工程无硬编码十六进制颜色

### Day 3 · 11-12（周四）｜数据层

- [ ] **目标**：五张表可读写，事务可靠
- **任务**：
  1. SQLite 接入 + Repository 抽象接口（数据层只被引擎/管理器依赖，架构规则 3.2）
  2. 建表：`SCT_Sample` / `SCT_CertifiedValue` / `CorrectionCoefficient` / `SCT_OperationLog` / `ControlLimit`（字段按任务清单第三节，含类型与主外键）
  3. 事务封装（写操作一律事务）；种子数据脚本（SUS-001~003 / CTL-001~004 / TS-6061-01）
- **产出**：数据访问层 + 建表脚本 + 种子数据
- **验收**：CRUD、事务回滚、外键约束单测通过

### Day 4 · 11-13（周五）｜SampleManager

- [ ] **目标**：样品档案与状态机正确运转
- **任务**：
  1. 样品档案模型与入库初始化（CurrentThickness = InitialThickness、UsageCount = 0、Status = Normal；位置绑定）
  2. 样品状态机：`Normal / NeedMeasure / Warning / Disabled` 及全部转移（UsageThresholdHit / HeightMeasured / ThicknessTooLow / ControlFail / ManualDisable / ReplaceSample，任务清单 P22）
  3. 使用次数与厚度控制逻辑（达阈值标 NeedMeasure；低于 MinThickness → Disabled + 报警事件）
- **产出**：SampleManager 模块
- **验收**：状态机全路径转移单测；边界（厚度=MinThickness）用例覆盖

### Day 5 · 11-16（周一）｜Modbus 通信基础

- [ ] **目标**：通信层可用，报文格式冻结
- **任务**：
  1. NModbus 连接管理：连接/断线重连/读写超时/重试上限（数值全部集中配置，编码规范禁止散落）
  2. **寄存器映射表设计**：TaskCommand / TaskStatus 结构体 → 保持寄存器块（定长、固定偏移、字节序约定）；SampleID/RackPosition 采用数字编号
  3. 映射表落 `config/`（版本化，含变更记录）；对照文档第六章 3.1/3.2 报文字段逐项核对
- **产出**：DeviceInterface 通信基座 + `config/寄存器映射表 v1`
- **验收**：映射表字段与任务清单报文定义一一对应；连接管理单测（模拟断连场景）

### Day 6 · 11-17（周二）｜PLC 模拟器

- [ ] **目标**：无真机可联调
- **任务**：
  1. `tools/` 下 C# 控制台 Modbus TCP 从站模拟器：保持寄存器区、TaskCommand 命令寄存器→TaskStatus 应答寄存器握手、心跳递增寄存器
  2. 故障注入开关：超时不应答、错误码回填（1001/1002/2001/3001/9001）、状态步进模拟（抓取→放置→激发中→完成）
  3. 与主程序联调：读写寄存器互通
- **产出**：PLC 模拟器（含使用说明 README）
- **验收**：主程序经模拟器完成一次完整"下发→状态流转→完成"演练

### Day 7 · 11-18（周三）｜任务下发通道

- [ ] **目标**：任务可靠下发
- **任务**：
  1. TaskCommand 编解码器（含数字 SampleID/RackPosition 编码约定、CRC/序号防错位）
  2. 命令握手：命令寄存器写值 + 应答寄存器读值确认（超时/失败走错误链）
  3. 下发前预检门：SafetyOK / RobotReady / SparkStandReady 任一为假拒绝下发（硬性规则 5）
- **产出**：DeviceInterface.SendTask 完整实现
- **验收**：编解码往返一致性单测；预检拒绝路径单测

### Day 8 · 11-19（周四）｜状态反馈与心跳

- [ ] **目标**：状态实时可见，断线可感知
- **任务**：
  1. 状态轮询 + 变化检测（周期集中配置）；TaskStatus/设备就绪信号解析
  2. 心跳：1–2s 递增计数寄存器交换，超时判定 → 进入安全状态（暂停任务、报警）
  3. 登记错误码：4001 PLC 心跳超时、4002 寄存器校验失败（先登记 11.1 表再使用）
- **产出**：DeviceInterface 状态订阅（轮询）层 + 错误码登记更新
- **验收**：模拟器注入"心跳停跳/超时不答"场景，主程序按预期进入安全状态并产生 4001 日志

### Day 9 · 11-20（周五）｜错误链路闭环

- [ ] **目标**：错误从发生到落库全程可追溯
- **任务**：
  1. LoggingAlarm：统一错误码表常量（开发规范 11.1 全表）、AppError 业务异常类型
  2. WPF 全局异常兜底（DispatcherUnhandledException / AppDomain.UnhandledException / UnobservedTaskException）
  3. Serilog 结构化日志（必含 TaskID / SampleID / 状态机步骤 / 设备）；错误写入 `SCT_OperationLog`（ResultStatus）
- **产出**：LoggingAlarm 模块最小闭环
- **验收**：模拟器上跑通"下发 → 反馈 → 注入异常 → 日志 + 落库"全链路演练

### Day 10 · 11-23（周一）｜M1 集成验证与收口

- [ ] **目标**：里程碑 M1 达成
- **任务**：
  1. 模拟器全场景回归：正常流程 / 超时重试 / 3001 安全门 / 9001 急停 / 心跳中断
  2. `dotnet build` + `dotnet test` 全绿；AGENTS.md 硬性规则逐条自查
  3. 更新开发规范（实施优先级进度标注）；打 tag `M1`
  4. M2 细化：把核心引擎两周拆成每日任务（更新本文档）
- **产出**：M1 标签 + M2 每日计划
- **验收**：Host PC ↔ PLC（模拟）任务通道全通；所有场景行为符合任务清单与开发规范

## 4. 跟踪规则

1. 每日开工先看当日条目；完成一项勾一项 `[x]`。
2. **拖期处理**：不顺延后续日期——未完成项移入周末缓冲；连续两天拖期需重估后续粒度并更新本文档。
3. 每日收尾：`dotnet build` + `dotnet test` 绿 → conventional commit（中文）→ push。
4. 阻塞（如真机/协议依赖）超过半天：记入当日"阻塞"备注并调整当日范围，优先做无依赖任务。
5. 每个里程碑结束：tag（M1/M2/…）+ 更新本文档进度 + 下一阶段细化。
