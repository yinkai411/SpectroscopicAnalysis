## 3. 架构规则

### 3.1 模块职责（与任务清单第十二节一致）

| 模块 | 职责 |
|---|---|
| SampleManager / SCTSampleManager | 档案、位置、次数、厚度、状态 |
| SctStrategyEngine | 触发判断、样品选择、优先级调度 |
| WorkflowOrchestrator | 流程状态机、设备编排 |
| CorrectionEngine | 系数计算、应用、版本管理 |
| DeviceInterface | PLC（当前 Modbus TCP，预留 OPC UA）/ GNR / 铣床通信封装 |
| VisionModule | 图像处理、选点、测高 |
| LoggingAlarm / AuditLogger | 全流程日志、报警、错误收集 |

### 3.2 依赖方向（禁止违反）

```
UI (WPF/MVVM)
  → Workflow（编排/状态机）
    → SampleManager / SctStrategy / Correction / Vision
      → DeviceInterface / 数据访问层（Repository）
```

- 禁止反向依赖、禁止跨层直调（如 UI 直接调 DeviceInterface）。
- 模块间通过接口通信，接口定义在被依赖方。
- **DeviceInterface 必须保持抽象**：定义 `ISendTask / IGetTaskStatus / IMeasureHeight / INotifyTaskEnd` 等接口，Modbus TCP 与 OPC UA 作为可替换实现。

## 4. 编码规范

- 命名：类型/方法/属性 PascalCase；局部变量/参数 camelCase；私有字段 `_camelCase`；接口以 `I` 开头。
- 文件作用域命名空间（file-scoped namespace）。
- 项目启用**可空引用类型**（`<Nullable>enable</Nullable>`）与 `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`。
- I/O（通信、数据库、文件）一律 async/await，禁止 `.Result` / `.Wait()` 阻塞。
- 注释与日志一律**中文**；注释解释"为什么"，不复述代码。
- 禁止 magic number：错误码、状态值、寄存器地址必须使用具名常量/枚举。

## 5. 数据规范（依据任务清单第三节）

- 数据库维护 5 张核心表：`SCT_Sample`、`SCT_CertifiedValue`、`CorrectionCoefficient`、`SCT_OperationLog`、`ControlLimit`。
- **原始数据与校正后数据必须同时保存**，任何情况下不得覆盖原始强度/浓度。
- 校正系数**版本化**管理（IsCurrent / Version，旧版本归档不删除）。
- 系数变更必须写审计日志（变更前后值、时间、原因、来源样品、操作者）。
- 所有写操作使用事务。

## 6. 通信规范（Modbus TCP）

- TaskCommand / TaskStatus 结构体映射为**保持寄存器块**（定长、固定偏移），映射表放 `config/` 下版本化维护，双方按表联调。
- `SampleID` / `RackPosition` 使用**数字编号**，规避寄存器字符串编码问题。
- 状态获取采用**轮询 + 变化检测**（Modbus 无订阅机制）；轮询周期集中配置，不散落硬编码。
- 命令握手：命令寄存器写值 + 应答寄存器读值。
- 心跳：递增计数寄存器，1–2 秒交换；任一方超时进入安全状态。
- 模式切换（Auto/Manual/Maintenance）必须双方确认。

## 7. 状态机规范（与任务清单一致，枚举命名必须一致）

- 系统模式：`Manual / Auto / Maintenance / Emergency`
- 任务状态：`Idle → Registered → Preparing → Milling → Placing → Analyzing → Archiving → Completed / Failed`
- SCT 子状态：`Selecting → Retrieving → MeasuringHeight → Milling → Analyzing → UpdatingCoeff → Returning`
- 样品状态：`Normal / NeedMeasure / Warning / Disabled`（转移规则见任务清单 5.2/P22）

## 8. Git 规范

- 分支：`main`（受保护）+ `feature/<描述>` / `fix/<描述>`。
- Commit message：conventional commits，中文描述，如 `feat: 实现设置样标准化系数计算`、`fix: 修复测高后抓取高度未刷新`。
- 提交前必须 `dotnet build` 通过（后续加入测试后须 `dotnet test` 通过）。

## 9. 测试规范

- 框架：xUnit；测试工程 `tests/SpectroscopicAnalysis.Tests`。
- DeviceInterface 通过 **Modbus 模拟器**（tools/ 预留）或接口 mock 测试，不依赖真实 PLC。
- **必须单元测试**的核心：SctStrategy（触发判断/样品选择）、Correction（单点/两点标准化、干扰校正迭代）、Workflow（状态机转移）、SampleManager（次数/厚度状态转移）。

## 10. 安全规范

- 密钥、连接串、口令一律不入库；通过 `config/` 本地配置或环境变量注入，`config/` 中仅提交模板（`*.template`）。
- Modbus TCP 明文无认证：PLC 通信网络须独立 VLAN / 防火墙白名单（详见任务清单第二节选型说明）。

## 11. 错误收集与避免机制

### 11.1 统一错误码表（集中定义于 LoggingAlarm 模块）

沿用任务清单第九节错误码，并按段扩展规划。**新增错误码必须先在本表登记，再写代码使用；代码中禁止直接写数字错误码。**

| 段 | 含义 | 已定义 | 示例 |
|---|---|---|---|
| 1xxx | 机器人/物料 | 1001 机器人抓取失败；1002 样品未检测到 | 1003 抓取高度异常（预留） |
| 2xxx | 激发台/下压 | 2001 激发台下压异常 | 2002 力控反馈超限（预留） |
| 3xxx | 安全 | 3001 安全门打开 | 3002 围栏入侵（预留） |
| 4xxx | 通信（PLC/GNR/铣床） | —（新增登记） | 4001 PLC 心跳超时、4002 GNR 拒绝循环（预留） |
| 5xxx | 数据与业务校验 | —（新增登记） | 5001 样品厚度低于阈值、5002 系数计算失败（预留） |
| 9xxx | 系统/急停 | 9001 急停 | 9002 未捕获异常兜底（预留） |

### 11.2 错误收集链路

```
代码捕获/抛出异常（携带错误码 + 上下文）
  → 全局异常兜底（WPF DispatcherUnhandledException +
     AppDomain.UnhandledException / TaskScheduler.UnobservedTaskException）
  → 结构化日志（Serilog，必含 TaskID / SampleID / 当前状态机步骤 / 设备名）
  → 入库（SCT_OperationLog.ResultStatus + 报警记录）
  → UI 报警面板（分级展示：提示 / 警告 / 故障 / 急停；颜色/图标/提示音规则见[界面设计规范](./界面设计规范.md)第 7 节）
  → 错误统计（按设备 / 错误码段 / 时间维度汇总，供复盘）
```

**规则**：

- 禁止空 `catch`、禁止捕获后不记录不处理（吞异常）。
- catch 必须携带上下文重新抛出或转为带错误码的业务异常，不得丢失堆栈。
- 每条错误日志必含：错误码、发生时间、任务/样品上下文、设备、堆栈（系统级）。

### 11.3 运行时防错（避免机制 · 运行层）

- 所有设备通信调用**必须带超时与重试上限**（超时值、重试次数集中配置）；重试耗尽按错误码走报警链路。
- 任务下发 PLC 前必须**预检**：`SafetyOK`、`RobotReady`、`SparkStandReady` 全为真才允许下发。
- **样品位置一致性校验**：样品实际位置与软件记录不一致时拒绝切入自动模式（任务清单第九节硬性要求）。
- 手动操作与自动任务使用**模式锁**互斥；SCT 执行期间暂停生产样品分析。
- 数据库写入一律事务；关键状态转移前先校验前置状态合法（状态机不允许跳跃转移）。

### 11.4 编码防错（避免机制 · 编码层）

- 可空引用类型启用；公共方法入参显式校验（null / 范围），失败抛 `ArgumentException` 系。
- `.editorconfig` + Roslyn 分析器全量启用，警告视为错误。
- 禁止 magic number（错误码、寄存器地址、状态值一律具名常量）。
- async 方法禁止 `async void`（UI 事件处理器除外，且必须 try/catch 包裹）。

### 11.5 流程防错（避免机制 · 流程层）

- 提交前 `dotnet build`（及 `dotnet test`）通过；分析器警告即失败。
- 代码审查 checklist 必含错误处理项：是否走统一错误链？错误码是否已登记？超时/重试是否配置？上下文是否完整？

### 11.6 持续改进闭环

- 错误日志**定期复盘**（建议每迭代/每周）：按错误码归类统计，找出高频错误。
- 重复出现 ≥2 次的错误，必须升级处理：补充单元测试 / 增加预检规则 / 更新本规范或审查 checklist。
- 错误码废弃时在 11.1 表中标记 `[Deprecated]` 并注明替代码，不删除条目。

## 12. 实施优先级（与任务清单第十二节一致）

1. **Modbus TCP 任务下发与状态反馈**（寄存器映射 + 轮询，打通 Host PC 与 PLC）
2. GNR 协议（100–140）基本激发流程
3. RESULT_DATA_REQUEST 扩展
4. 系数计算（先单元素再干扰校正）
5. 干扰系数回归工具（离线）
